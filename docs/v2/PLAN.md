# V2：鸿蒙体验改造

## 目标与边界

保留视频、番剧、直播、弹幕、账号、下载、分享等业务流程和主要信息布局。
在“鸿蒙特色功能”中提供可关闭的鸿蒙风格；优先改善 Mate XTS 双折、三折展开体验。
V1 标签 `harmony-v1.0.0` 作为回退点。

## 实施顺序

| 优先级 | 内容 | 验收标准 |
| --- | --- | --- |
| P0 | 整理版本库、保存 V1 | 来源、构建、许可证、版本快照可追溯 |
| P0 | 展开屏原生 Dock | 鸿蒙风格下展开不自动变侧栏；页签/滚动保留；分屏可用 |
| P0 | 封面过渡修复 | 只让封面区域参与过渡；不拉伸全卡片/页面；返回及快速退出无异常 |
| P1 | 鸿蒙风格开关与共享组件 | 关闭保持原风格；设置分组、分栏、开关、按钮、弹窗统一；大字体无截断 |
| P1 | 系统智感握姿 | 可单独开关；先使用 HDS 原生握姿适配；不支持时稳定显示，不模拟传感器结果 |
| P1 | HAP 与回归 | 业务编译通过，新增测试通过；记录实际真机结果 |
| P2 | 全页面细节打磨 | 搜索、评论、动态、弹幕设置、下载、个人页等逐页对齐，保留原交互 |

## 实现依据

- SDK 26 的 `HdsTabsFloatingStyle.adaptToHandedness` 提供系统随握姿显示能力（API 23 起）。
- 现有原生 Dock 已使用该能力，但窗口宽度达到 600 时 Flutter 切侧栏并隐藏 Dock。
- 现有 Hero 把完整卡片变换到整页详情，源与目标纵横比差异会导致封面突兀放大。
- Flutter 承担既有业务界面；系统 HDS 承担原生导航与握姿。鸿蒙风格组件复用同一业务状态，避免双份业务逻辑。
- 完整重写全部页面为 ArkUI 会扩大回归范围；本版先通过共享风格与关键原生组件覆盖现有页面。

## 工作量评估（单人开发估算）

- 核心首批：约 4–7 个开发日（Dock、封面、可选风格、设置大屏及握姿开关）。
- 全页面样式细化：约 2–3 周，取决于各自自绘控件、弹层与特殊播放器页面。
- 三形态真机与性能回归：约 3–5 个测试日；握姿还取决于设备系统设置和实际能力。
- 若要求每个控件都改用 ArkUI 原生实现，预计再增加 4–8 周，并需重做 Flutter/ArkTS 状态协调。

以上是范围估算，不把首批完成等同于所有页面都已完成原生化。

## 必测场景

折叠/双折/三折、横竖屏、分屏、字体放大、深浅色、开启/关闭鸿蒙风格、左右手切换、快速进入/返回视频、播放中折叠、后台/画中画、已有账号和下载记录保留。
