# V2.6.5 · 视频比例入口、连续预取与布局

开启“竖屏短视频模式”后，默认入口按视频本身的比例判断：高大于宽进入短视频，横屏视频打开普通详情；未知尺寸先用普通页，取到真实尺寸后只校正一次。用户手动进入/退出优先，不因信息流下一条的比例不同而突然退回详情。设置开关、离线、番剧和播放列表的原有范围保持不变。

## 连续滑动的预加载

旧实现仅准备下一条，并等待当前缓冲超过 3 秒；快速换条会取消未完成的媒体预取。新版在取得推荐列表后准备后面三条，滑到目标页一半时提前调整预取窗口，等页面吸附结束才更换当前源，保持同一个播放器。

取流结果按视频、CID、账号、画质、编码、语言与线路等条件隔离，最多保留 4 个条目、45 秒；正在取流的目标由前台复用同一请求。退出、切换上下文、移出窗口或超出 8 秒预算时取消相关后台请求。

预加载真实视频开头（每条最多 768KiB）和音频开头（128KiB）。本机回环 Range 服务把这些数据交给已有原生播放器；收到校验过的首段 64KiB 后即可供读取，不必等待整段完成。缓存头部立即发送，缺失的尾部按 Range 续取。正常窗口为当前与后面三条，交接时最多 10 路媒体前缀，每路硬上限 1MiB。播放用 URL 在切换中保留，缓存异常沿用有限次数的原地址重试。

短暂的缓存交接/解码阶段不立即闪出加载文字，超过 300ms 的真实等待仍保留原加载与重试入口。此实现预取地址和媒体字节，没有启动第二个解码器预渲染；网络不足、超出预取窗口或解码耗时仍可能等待，不能宣称任意网络和滑动速度都零等待。

## 截图对应布局

- 信息层显示：右侧操作、作者/关注和简介；底部通栏细进度条与弹幕胶囊。
- 简洁状态：播放/暂停和时间在进度条上方，底部弹幕与模式按钮保留；视频几何不因信息显隐改变。
- 拖动：突出进度条和底部时间，暂隐信息层；不再重复显示原播放器顶部时间提示。
- 评论：手机上方保留视频，评论在下方展开；展开屏采用并排区域。动画保留同一播放器，分页暂时禁用，系统返回先关闭评论。紧凑标题/排序、评论数量、关闭和底部回复入口复用原业务。
- 三点菜单将我不想看、稍后再看、缓存、小窗播放、投屏放到快捷操作区，其余设置仍可用。没有伪造微信、QQ 等未接入的分享入口，也不复制截图中视频特有的推荐词或免责声明。

视觉参考为本次用户提供的七张 iOS B 站截图。现有功能入口与鸿蒙配色/字体可访问性继续保留。

## 公开资料与实现边界

[B 站技术：视频体验进化之路](https://www.bilibili.com/opus/316069138693788728)（2019）介绍了播放地址和起播数据预取、减少首帧前串行工作。它讨论的是当时的播放页优化，并未公开现行 iOS 短视频客户端的完整算法，不能将本版实现声称为官方内部实现。

[mpv 官方缓存文档](https://mpv.io/manual/stable/#cache)区分缓存、解复用和播放缓冲。实际首帧还需要解码/渲染，因此网络预取与零首帧体验不等同。
