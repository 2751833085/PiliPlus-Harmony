# V3.0 正式 Beta：全界面改造范围与实施计划

状态：实施与验收中（2026-09-24）。代码候选：3.0.0+6200；回归基线：3.0.0+6125。具体完成情况见 BETA_VALIDATION.md。以下保留最初范围及诊断记录，其中“仅计划/尚未修改”等表述是规划时点记录，不能代表当前实施状态。用户已明确只保留鸿蒙风格；先确定完整范围，再统一实施和交付，不边改边扩大目标。

本计划覆盖自有可见界面及交互组件。保留现有功能、账号数据和偏好；未获明确指示的业务功能不删除。已有 FEASIBILITY.md 为历史研究，材料中的版本、估算和官方客户端观察不能视为本次最新验证。

## 一、已确定的产品边界

1. 移除 Material You 风格开关及对应外观分支，应用只呈现鸿蒙风格。不再提供两套显示模式。
2. 保留颜色选择（默认粉色）、明暗模式、纯黑主题、字号和沉浸光感开关。强调色只用于关键动作/选中态，页面、气泡、评论回复和菜单使用一致中性色。
3. 保留用户认可的首页现有布局和设计，不重做首页。我的、设置和播放页保留主要布局，整理材质与控件细节；搜索展开页按最新要求重构为纵向分区，首页搜索栏本身保留；动态统一为协调的卡片式信息流。消息和聊天继续执行已确定的分栏改造；所有页面的弹出菜单、对话框和提示统一配色与沉浸光感，包括开启无痕模式的提示。
4. 消息中心采用类似微信的列表—内容分栏方式：展开且空间足够时左侧列表、右侧会话或通知详情；窄屏逐级进入。不是强行在单屏塞两栏，也不要求复制微信颜色。
5. 保留普通播放和短视频模式的业务与进入规则：开启短视频后仅竖屏自动进入，横屏默认普通页；保留手动切换。保留新修复的详情/头像/进度条随页翻动。
6. 面向用户统一一次交付；内部按可验证的阶段提交。功能删减和合并另行明确，不把删除 Material You 解释为删除视频能力或设置。

## 三、公共组件先统一

- 颜色：页面/分组/浮层/输入背景、正文/次要文字/禁用态、细分隔线、强调色、反馈状态独立命名；深浅色与纯黑分别有明确映射。
- 尺寸：字体层级、图标视觉大小与触摸区域分离；按钮、头像、输入栏、行高、圆角和间距集中定义，避免单屏和展开态分别硬编码。
- 光感：Dock 为参考，固定工具栏和覆盖面板可用有限模糊；长列表中的卡片/按钮优先采用轻量高光和渐变。不开启光感时仍保持完整的鸿蒙样式。
- 弹出视觉（本轮重点）：所有页面的 Popup、底部面板、确认框、警告/说明框、Toast/Snackbar 和操作结果提示统一颜色、文字层级、圆角、边框及沉浸光感，包括开启/关闭无痕模式的提示。检查浅色、深色、纯黑和光感关闭状态，避免某个旧弹窗仍使用突兀的亮灰底或旧主题色。短暂文字提示采用轻量同款材质，不强制增加实时模糊。
- 弹出规则：设置枚举/调色等短选择就近展开；视频条目三个点的编辑/管理动作及简短选择优先就近展开；分享、合集等较长操作面板可贴底；长内容在宽屏可用侧面板；确认对话框居中。避免一个规则套全部窗口。
- 交互：统一返回优先级（输入法/表情 → 最上层弹层 → 当前内容页 → 上级）；统一转场、切页、加载、刷新、重试和无障碍状态。首屏一个加载提示，不恢复满屏占位框；保留目前已恢复的原版刷新方式；稍微降低首页触发距离，仍需达到阈值后松手才请求，短拉取消、按住不刷新；刷新指示器背景补轻量光感。
- 背景和安全区：所有页面统一覆盖至系统边缘，内容避让挖孔/手势区/键盘/Dock；底部渐变不制造黑白断层。

## 四、消息双栏的结构与状态

宽屏：左栏放消息分类与会话列表，右栏显示选中会话/通知详情；不额外固定第三栏。初步以左栏 280–340dp、右栏至少 360dp 作为原型范围，结合安全区和文字缩放决定是否分栏，最终数值需真机冻结。

窄屏：消息列表 → 聊天/通知详情，保留返回路径。二折/三折/旋转/分屏时按可用空间响应，不按设备名称判断。切换形态必须保留选中会话、草稿、滚动位置及输入状态；右侧只维持当前会话，不给每一行创建聊天控制器。

当前 WhisperDetailController 从 Get.arguments 读取会话身份，且加载会确认已读。需要先引入显式会话参数/可嵌入内容组件，并将路由壳与聊天主体分离，保证双栏不会误读全局路由参数，也不会因预览所有会话而全部标记已读。复用现有消息协议和业务接口。

## 五、移除 Material You 的边界

- 移除可见开关、重启切风格提示、MD 配色/调色板专属选项和失效禁用提示；保留独立强调色选择。
- 迁移旧 materialYouUI/harmonyUI 配置：升级统一进入鸿蒙 UI；保留其他用户选择，不清空设置或重置颜色/导航/播放选项。
- 自有 UI 逐步只依赖项目的鸿蒙组件和设计变量，删除双套页面与样式条件。HarmonyStyle/Pref.harmonyUI 当前承担平台/风格判断，不能机械全局替换而破坏平台能力判断。
- Material You 显示的删除是本次确定范围。Flutter/GetMaterialApp/第三方库的间接 Material 依赖另列技术清理清单；不通过删 import 冒充外观改造完成，不把本次自动扩成整个 ArkTS 跨语言重写。
- 非鸿蒙平台目录、协议/下载/播放器底层大结构不在本次默认删除范围；系统自带授权/分享窗口和远端网页正文只改自有宿主部分。

## 六、实施顺序与交付门槛

1. 冻结本清单及功能去留台账，保留 6125 作为已归档基线。
2. 建立全局设计变量/组件，以现有“我的”卡片和首页搜索栏为视觉/互动参考，完成弹出菜单/无痕提示、消息双栏、设置控件与评论按钮的代表性样板；同时确定单屏/展开/大字号尺寸。
3. 先打通主流程与消息双栏，再迁移表中剩余页面和弹层；一个组件只有一套实现。首页、我的、设置和播放页保留主要布局，动态统一卡片式信息流，搜索展开页采用纵向分区。
4. 统一迁移配置并移除 Material You 可见入口和无用分支；检查设置搜索及所有多 Tag 入口。
5. 全量检查、性能对比、签名升级验证，最后统一交付正式 Beta。内部可以分多次本地提交；未另行授权不自动推送或发布。

每个页面必须核对：浅色/深色/纯黑、默认粉色/自选色、沉浸开关、正常/大字号、游客/登录、加载/空/失败/完成状态，以及单屏/二折/三折、横竖/分屏和安全区。物理折叠与握姿必须用真机确认，不能以修改模拟分辨率代替。

必测流程：首页到视频到评论/合集到返回；短视频连续快滑/回滑/暂停/隐藏详情；旋转锁定与折叠播放；消息列表到聊天及带草稿折叠；收藏/历史/下载/搜索/动态编辑；覆盖升级保留账号和缓存。测试发消息/发布/投币/点赞等账号写操作需使用明确授权的测试对象，不向他人发送试验消息。

性能：先记录 6125 同设备、同场景的帧耗时、连续翻页首帧、内存与切页表现，再比较 Beta；限制实时模糊、避免重复播放器和全列表重建。未测得基线前不宣称已消除全部卡顿。

## 七、留待定稿的事项

- 消息双栏宽度、列表密度、全局材质强度通过代表性样板冻结；不在大量页面改完后再分别调参。

本轮仅写入计划与静态入口清单，没有修改应用运行代码、安装新包或开始正式 Beta 重构。

### 新增服务的实现边界

新增“我的服务”和“订单中心”属于功能扩展，不是占位装饰。首批服务明确含课程、装扮，其他项目待清单确定，不凭空添加。现有主入口只有离线缓存、观看记录、订阅和稍后再看；虽然项目有课程相关内容模型，不能据此认定已具备完整课程/装扮商城或订单接口。

实施前核查可用且受支持的官方服务入口、登录态与返回路径。可复用官方服务页面时由统一宿主承载；有明确可用接口再实现自有内容页。需覆盖游客提示、登录过期、加载失败、外部跳转及返回；服务不可用时给出真实说明，不放假订单、空壳页或宣称已经完整实现交易系统。该范围包含真实服务访问，不默认扩展为自建支付/退款系统。

### 互动材质的共用方案

以现有首页搜索栏的可互动材质及 Dock 为参考，统一“静止—按下—轻拖—释放”状态。用户已明确：所有应用沉浸光感的按钮和控件都必须具备随手指位置移动的高光、轻拉时的弹性位移/形变，以及松手回弹；参考当前 Dock 和首页搜索栏。该交互是局部弹性反馈，不增加自由摆放或保存新位置功能。开关只反馈当前交互，不与开关本身的拖动切换冲突；页面滚动、视频拖动、长按、点击采用明确的手势竞争规则。支持减少动态效果/高对比度，无此能力时保留静态同款表面。

将卡片/提示/菜单/输入框分成少量材质等级，颜色保持一致而非每项都强模糊。列表默认轻量渲染，固定或覆盖区域限制模糊面积；本轮不恢复早期逐按钮模糊造成的滚动开销。


## 九、统一光感交互验收（已明确）

适用范围：所有启用沉浸光感的按钮及控件，包括顶栏动作、搜索/输入入口、关注/评论/播放全部按钮、设置开关和选择控件、菜单与提示面板等。不能只补背景、描边或静态高光；已适配材质的旧控件同样需要检查互动反馈。

统一状态：
1. 手指接触时，高光出现在实际触点附近；移动时高光连续跟随，不能固定在控件中间。
2. 轻拉时产生受限的弹性位移或形变，阻尼和视觉强度与当前 Dock、首页搜索栏协调。
3. 松手或手势被取消后平滑回到原位，清理高光；页面切换、列表回收、折叠或应用进入后台后不能残留变形状态。
4. 不改变控件原本点击/切换/输入语义，不抢占列表滚动、开关滑动、视频调进度、长按等既有手势。滚动获胜时取消局部拉动，不顺带触发按钮。
5. 以统一交互表面组件实现并批量接入，不逐页面复制动画。嵌套表面只由最内层有效交互目标响应，避免一次触摸多个控件一起弹动。
6. 普通设置下全部覆盖；关闭沉浸光感时按原偏好回退，系统减少动态效果/高对比度下提供适当降级。无人触摸时不持续运行动画；高光与形变只重绘局部，不引起整页重建或为每个列表项增加实时模糊。

验收须包含浅/深/纯黑色、边缘触点、快速反复点击、轻拖/取消/松手、列表滚动、折叠重布局、大字号及多个相邻控件，检查高光位置、回弹、误触和滚动性能。


## 十、智感握姿：优先修复真实握持驱动

用户反馈：当前体验更像按左右滑动位置换边，不能可靠反映实际持握。明确目标为左手握持靠左、右手握持靠右、双手握持居中，而非根据最后一次触摸位置推测持握。

代码核查（6125 基线）：
- SystemPosture.ets 已订阅 motion.holdingHandChanged，并映射 LEFT/RIGHT/BOTH 为 left/right/center；结果通过 MethodChannel 发至 Dart。声明文件确认该接口要求 DETECT_GESTURE，工程已声明此权限，但声明本身不证明设备已授予或回调有效。
- Index.ets 的原生 HdsTabs 使用 barFloatingStyle.adaptToHandedness；没有直接接收 SystemPosture 的 side。Flutter 的 HarmonyHandDock 则监听 MethodChannel 的 handSide。原生 Dock 和 Flutter 控件尚未由同一份明确状态统一驱动。
- 当前注册监听成功就上报 available=true，无法区分“订阅成功但尚无有效握姿”和“已识别”；异常被吞掉，缺少可诊断原因。
- 当前 180ms 去抖每次回调重置计时，需验证重复同值事件是否可能延后落定；不是先盲目缩短延迟。

修复范围：
1. 核实 Mate XTs 当前系统的能力、实际权限、订阅是否成功，以及换手/双手握持是否返回有效事件。仅记录状态、时间和错误码，不采集触摸内容或账号数据。
2. 建立统一状态源供原生 Dock 和 Flutter 控件使用；真实 holdingHandChanged 结果优先，禁止最近触摸侧覆盖有效握姿。核实原生组件能否显式定位且保留现有光感/弹性；必要时调整宿主定位，不能与内部自动换边同时竞争。
3. 区分左、右、双手、未握持、未知、不可用、等待首个有效结果。左/右/双手按用户要求定位；短暂未知保留稳定位置，持续未握持的居中策略需真机验证，不根据单次噪声跳动；能力不可用时保持居中并清楚显示状态，不冒充识别成功。
4. 稳定状态更新不被重复同值样本无限推迟；换手短暂过渡去抖，明确双手状态允许居中。触摸/拖动 Dock 时冻结位置，释放后应用最新稳定握姿，避免目标在手指下移动。
5. 返回前台、折叠展开、旋转、开关重启订阅后恢复有效状态；注销旧监听，避免重复回调、缓存过期或回到默认侧。
6. 真机验证左手→右手→双手→放桌面，不依赖屏幕滑动；保持左手握持时在右侧滑动也不应被错误改判为右手。单屏/二折/三折、方向切换与后台恢复分别记录。系统识别是否有效必须用物理持握确认，UI 注入点击不能代替。

参考：[华为多设备适配指南中的智感握姿](https://developer.huawei.com/consumer/cn/multidevice/adaptive-apps/)明确区分左手、右手、双手及未握持。本轮核查以本机 API 26 SDK 声明及项目源码为实现依据，尚未取得真机握姿事件记录，不能断言根因已完全确认或功能已修好。

当前仍为计划与诊断阶段；此项排在正式 Beta 的互动材质全面接入之前，先修正布局驱动来源，再统一表现。


## 十一、Dock 可读性与搜索展开页（最新范围）

### Dock 不应过透

用户反馈 Dock 太透明，内部文字和图标不易辨认。提高材质底色的遮蔽能力、调整模糊与中性色衬底，并统一选中/未选中图标和文字对比度；保留原有光感高光、弹性互动及悬浮布局，不靠把所有图标加粗或更鲜艳来掩盖背景干扰。

现有 Index.ets 原生 Dock 在沉浸模式下显式使用透明 barBackgroundColor，配合 IMMERSIVE/ADAPTIVE 材质。需检查两处导航宿主及 Flutter 回退版本，找出实际生效配置；透明参数是核查点，不等于已经证明唯一根因。避免直接叠一个不透明矩形而破坏圆角和原生材质。

验收背景覆盖浅/深页面、白底卡片、彩色高对比封面和滚动中的内容；浅色/深色/纯黑以及光感开关分别验证。触点高光不能遮蔽文字；可访问性高对比度时采用更稳定底色。透明度最终按真机观感冻结，不在计划中臆定一个适用于所有系统材质的数值。

### 搜索展开页按原版方向重构

首页已经认可的搜索栏保持不变；此处指点击后进入的搜索页。单屏和展开态均采用纵向区块：顶部搜索输入区，随后是热搜、搜索历史、搜索发现。取消展开态将热搜/发现与历史放在左右两栏的布局。宽屏通过合理内容最大宽度、边距以及区块内部词条排布控制比例，不将文字拉满整块三折屏。

热搜标题右侧显示“完整榜单”，点击进入完整热搜列表，返回保留输入内容及列表位置。当前已有 /searchTrending 路由、完整榜单按钮与对应页面，优先复用真实数据/导航能力，调整位置、层级和材质，不新建重复页面。热搜/搜索发现的已有显示开关及历史记录隐私设置继续生效；关闭某区块后自然收起，不强行恢复用户隐藏的内容。

统一搜索框、历史词条、热搜排名、完整榜单入口与加载/空态/失败/清空确认的光感和过渡。键盘、搜索建议和提交行为保留，输入时避免建议与静态推荐区域相互挤压。搜索结果页的筛选及结果能力不因本次展开页重构而删改。

上述内容覆盖计划中此前“搜索保留主布局”的表述；本轮仅更新范围与代码核查，未修改运行代码。


## 十二、底栏仅保留两种选择（最新决定）

外观设置中的导航样式统一为：

- **悬浮**：保留当前悬浮 Dock，距屏幕边缘有间距；修正过透问题，保留触点高光、弹性回弹和有效系统握姿驱动的左右/居中定位。
- **经典**：原版固定贴底导航，横向铺满可用区域，与页面底部衔接，无悬浮外边距；内容区避让其高度和系统手势安全区，文字/图标遵循统一鸿蒙配色。经典布局保持固定，不随握姿左右移动。

仅保留上述两个用户可见选择，移除侧栏选项及“展开时也采用悬浮 Dock”等重复导航控制；展开/旋转后维持所选类型，不因宽度变大自动切到侧栏。消息、设置的内容分栏独立保留，不属于本条所取消的主导航侧栏。

升级迁移：既有悬浮 Dock 用户保持悬浮，既有固定底栏用户映射经典；原侧栏用户映射经典作为最接近固定导航的方案。保留标签内容、顺序、默认页和无关设置。使用明确旧枚举映射，禁止直接缩短枚举后按旧索引读取导致错配；未设置偏好时保留当前默认悬浮。

智感握姿在悬浮模式生效；经典模式下该选项可保留入口但说明不影响固定底栏。两种样式均适配安全区、浅/深/纯黑、字号和光感开关；固定底栏不因材质互动产生可持久移动。检查切换样式时页面滚动位置和导航选中项不丢失。

本节覆盖前文及历史台账中的“悬浮 Dock/底部导航/侧栏三种可选”和展开强制侧栏规则，当前仅更新计划，尚未修改运行代码。
