# V2.6 · 展开刷视频与海外模式

应用版本 `2.6.0+6086`，继承 V2.5 的手动开启方式和 V2 的鸿蒙界面改造。

## 使用

在「设置 → 其他设置 → 播放器体验」开启「竖屏短视频模式」。普通 UGC 视频支持：

- 单屏、展开及横屏全屏采用同一分页组件，上滑下一条、下拉上一条。
- **在第一条，手指从上往下拉并松开**会重新请求推荐列表，第一条也换成不同的新视频。回到第一条的那次翻页不会顺便触发刷新。推荐请求失败、空列表或只有当前视频时，保留原队列和播放。
- 左右拖动调整进度，竖向手势留给翻页；全屏单击显示/隐藏控制栏，竖屏单击播放/暂停。进度条、长按倍速和已有播放器菜单继续可用。
- 全屏控制栏出现时可点「评论」，评论以弹层打开；控制锁开启后禁止翻页、刷新并隐藏评论入口。
- 展开宽屏使用完整可用宽度，切换全屏或换视频仍复用同一个播放器视图；从三屏折回单屏沿用退出全屏的设置。

番剧、直播、本地文件与批量播放列表保持既有界面，不强制变成信息流。短视频开关默认关闭，可随时回普通详情。

## 海外模式

「设置 → 其他设置 → 网络与加载 → 海外模式」，默认关闭，下次打开视频生效。适用于大陆以外网络的普通视频/番剧 DASH 播放；直播、下载、旧式分段流和本地播放保留原策略。

开启后手动 CDN 与“音频不跟随 CDN”暂不可选，点击解释原因，原值保留；关闭后恢复。默认画质、蜂窝画质与音质依然按用户选择，不自动降清晰度。

线路选择分别检查视频和音频。对服务端返回的 Bilibili `upgcxcode` 地址保留签名查询，尝试工程已有的 Akamai、阿里海外、腾讯海外三个域名；服务端原地址和一个备用地址参与回退。未知域名、文件地址与播放列表不改写。不能因此解除账号、会员或地区限制。

每条候选请求前 16 KiB，收到有效媒体响应后取消其他请求，单轮截止 1.6 秒。海外地址先尝试，原地址在 120 ms 后参与；5 分钟内成功过的域名先尝试。只缓存域名健康状态，不持久保存签名地址。探测不携带账号 Cookie，使用默认 TLS 证书验证。服务器忽略 Range 时会停止读取，但不宣称网络层流量能精确限定在请求范围内。

已失败的域名暂避 1 分钟，网络变化后清除线路记录；视频和音频网络错误最多触发两次换线路重开，保留进度与播放/暂停意图。请求与播放器初始化串行，关闭页面或换视频后丢弃旧结果。手动编辑播放地址仍优先采用用户输入。

目标画质已在首个响应中时，补齐其他画质不再阻塞开播；目标画质缺失时仍等待补齐。海外播放使用 8 秒 HTTP 网络超时，并在原缓存大小/时长上限内持续补充缓冲。相关参数含义依据 [mpv 官方手册](https://mpv.io/manual/stable/#network)与[缓存滞后参数说明](https://mpv.io/manual/stable/#options-demuxer-hysteresis-secs)；这是本项目的策略选择，实际首帧与持续吞吐仍需当地网络测量。

小块响应最快不代表整段吞吐一定最快，运营商、视频源和时间段都会影响结果。探测不可用时会尝试服务端地址，不会无限等待测速。
