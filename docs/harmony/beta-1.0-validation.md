## 本轮修复

- 播放器：源切换期间的旧进度请求、播放/暂停迟到回调、恢复播放的请求归属、画中画回调清理。
- 下载：取消与启动串行化，媒体空文件/超长 Range 拒绝，完成记录落盘成功后才移动完成队列。
- 搜索和动态：旧建议不能覆盖新输入，刷新和更换 UP 主使旧分页响应失效。
- 评论管理：刷新或排序后按根评论/子评论 ID 定位置顶、删除与举报结果，避免旧位置错行或空列表异常。
- 游客消息页：不再请求登录用户的未读数；离开页面或换账号后不展示旧响应/错误。
- 聊天：刷新与分页乱序保护，撤回按消息标识定位，页面退出后的图片上传回调不再继续发送，新草稿不会被旧发送结果清空。
- 原生宿主：解绑窗口安全区和底栏监听，释放旋转快照，拦截页面退出后到达的窗口回调。
- 更新：只选择当前发布中完整上传的签名 HAP；显示 Beta 1.0，保留递增内部构建号及兼容旧客户端的标签格式。

## 核查范围与边界

[逐项功能审计](beta-1.0-feature-audit.json)覆盖原功能清单的 147 项、26 组。逐项核查源码、对应自动测试及验证限制；没有把旧清单的未验证标记直接改成通过。删除的短视频设置、握姿 Dock 操作和点踩数量实验不恢复。

模拟器使用专用 HarmonyOS 7 / API 26 三折屏实例，游客状态。原生单/双/三屏分别为 1008×2232、2048×2232、3184×2232，DPR 2.875；不拉伸截图模拟屏幕。

横屏旋转未计为通过：官方旋转命令返回成功但实际窗口未旋转；尝试组合旋转/恢复操作时，自动审批因状态读回证据不足拒绝执行。随后用单步操作读回并恢复原旋转锁定设置。没有把命令成功视为实际旋转成功。

模拟器播放器依赖限制了真实视频纹理，无法代替真机验证解码、音画同步、弱网播放、功耗和外部音频中断。登录、发私信、投币、支付等账号动作不在游客实测范围。导航与滚动控制耗时包含 HDC 链路，不能当作实际 FPS。

## 转场采样

本轮预候选（同构建号，SHA-256 前缀 `e9e726ec`）按既有协议采集 3 次冷启动、15 次暖态设置页进退，共 36 个完整标记。最终包的 SHA-256 为 `388c330f…`，补充修改仅限游客消息与加载态；以下数值仍明确归属于预候选，不冒充最终包独立采样。

冷启动首次进入，从进入标记到首个匹配栅格片段结束的间隔为 12.746–21.220 ms（6251 基线 25.646–29.589 ms）；暖态进入 UI P95 为 3.395 ms、DoDraw P95 为 19.817 ms。暖态进入仍有 14/286、退出 6/283 个大于 25 ms 的相邻绘制间隔。暖态进入中的最长 DoDraw 样本为 50.013 ms，其中包含 47.930 ms SwapBuffers，而 LayerTreePaint 为 0.381 ms；另有退出样本出现系统 VSync 延迟。这只能定位到所采样链路，不能归因为特定优化或换算成真实手机 FPS。

结论：仍有偶发长尾，未确认所有设备转场无掉帧。实际真机和最终包的帧呈现应单独复验。
