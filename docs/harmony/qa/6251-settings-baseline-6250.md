# 6250 设置页转场基线

在 DevEco HarmonyOS 7 / API 26 三折屏模拟器上使用同一份 6250 生产签名包，游客模式，原生分辨率 3184×2232。测试先保留原值，再仅关闭「底栏沉浸光感」。全局「沉浸光感」始终开启，结束后读回底栏选项已恢复开启。

每组分别验证 3 次保留数据的应用冷启动后首次进入及返回，以及 15 次暖态进入及返回。先确认「我的」，点设置，确认设置页，再系统返回并确认「我的」。每组对应 36 个完整 Navigator 区间和 6 段原生 hitrace，环形缓冲的保留项数与写入项数一致。冷启动保留磁盘缓存。

| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: |

UI BeginFrame 分位数包含区间内全部完整 UI 片段。DoDraw 与 SwapBuffers 使用按进程及 Flutter 帧号匹配的 UI/栅格片段。每个转场单独计算相邻间隔；表中的超过 25 ms 间隔经原始 DoDraw 开始标记核对，中间没有被配对过滤掉的绘制。

两组暖态的 SwapBuffers 约占匹配 DoDraw 累计耗时的 88%–90%。关闭底栏光感后，暖态长间隔减少，VSync 报告时间戳到应用接收的最大值也下降，进入由 21.301 ms 到 18.178 ms，返回由 43.127 ms 到 23.153 ms。P95 则分别从 6.765 ms、8.631 ms 变为 8.041 ms、8.917 ms。

开启时最大的暖态返回间隔为 57.009 ms。上一帧 DoDraw 为 4.209 ms，下一帧 UI 为 1.126 ms。下一次系统 SendVsyncTo 比同一 VSync 报告时间戳晚 43.010 ms，发送后 0.117 ms 到达 Flutter，接收后 1.135 ms 开始 UI。其余开启组的暖态长间隔也能匹配系统发送及 Flutter 接收，发送到接收为 0.066–0.825 ms。跟踪中没有足够的线程调度事件来进一步确定系统发送为何变晚。

区间内的栅格片段可包含缓冲区等待。相邻 DoDraw 与 VSync 数据用于定位引擎供帧长尾，未与应用表面的实际呈现逐帧关联，因此没有计算 FPS、实际掉帧数或触摸到屏幕延迟。两组按固定顺序各跑一次，样本量有限，结果不足以把长尾归因于底栏材质。未在实体手机上测试。
